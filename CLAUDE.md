# parahouse site: notes for Claude Code

Studio website for parahouse (always lowercase), a Singapore design studio that works for agencies (not brands) on roadshows, exhibitions and brand events: concepts, 2D and 3D design, renders, technical drawings and print-ready artwork, delivered under the agency's name. parahouse is digital only; fabrication is the agency's fabricator. Positioning: "Your silent backend. We don't compete, we enable." Tagline (deck): "We build fast. You look good." Not used on the site, since parahouse doesn't build. Source of truth for copy is the 2026 capabilities deck.

## Stack
- Plain static HTML/CSS/JS in `public/`. No framework, no build step. Keep it that way unless asked.
- Hosted on Cloudflare Workers with static assets (`wrangler.jsonc`). `worker/index.js` only handles `/api/*`; everything else is a static file.
- Contact form posts to `/api/contact`, which emails via the Resend API. Secret: `RESEND_API_KEY`. Vars: `CONTACT_TO`, `CONTACT_FROM`.

## Design rules (references: Zeroframe first, then Foucault)
- Dark site. Tokens (colours, radius, gaps, fonts) are at the top of `public/assets/css/site.css`; use them. Ground is a fixed, slow gradient from dark red at the top of the screen (`--bg-top`) to near-black (`--bg`) below (`body::before`); cards use `--surface`, hairlines use `--line`. Project pages swap the red for the project's own colour: each project in `PROJECTS` has a `hue` (TSUBAKI red 356, PropW purple 268, ORA 5 teal 176, Cetaphil blue 222, Don Julio gold 40, 1664 blue 232; yellow-greens glare at this strength, so pick the nearest hue that does not), which sets three variables on that page's `<html>` at the same strength as the red they replace: `--bg-top` (background tint, and `theme-color`), `--brand` (accent: P logo, round buttons, current menu item, hovers) and `--curtain`. `window.PH_CURTAINS` (in every `<head>`) maps project URLs to their curtain colour, so the curtain rising toward a project page is already that project's colour; leaving a project page for any other page, the rising curtain is brand red (#4a0e12), so there is no colour jump when the next page lifts it. Other pages stay brand red.
- One fixed look: no time-of-day lighting and no light/dark toggle (removed at Nicholas's request; night was too dim).
- Type: Archivo at 125% width, bold, UPPERCASE for headings (`--display`: `.statement`, intro line, tile titles, service titles, menu links, footer wordmark). Geist for body text (`--font`). Geist Mono, small uppercase with letter-spacing, for labels and metadata (`--mono`: section bars, chips, buttons, pills, form labels, footer). All self-hosted in `public/assets/fonts/`.
- Brand red `--brand` (#e02c1d, a vivid pure red Nicholas picked; text on it is white) is the accent: the P logo, round buttons, the current menu item, hovers. On project pages it becomes the project's colour (see above).
- Logo: the red P mark (inline SVG, a traced stand-in until the original file is supplied), top-left, no text. On hover its two parts (`.p-head`, `.p-stem`) spring apart and back.
- Navigation: at the top of every page, Work / Services / About / Contact stack downwards top-right in large uppercase Geist (`.topnav`, current page in red with a dot to its left). After 120px of scrolling `site.js` sets `html.is-scrolled`; the links fade out and the glassy Menu pill (`.menu-toggle`) scales in, opening a compact panel (`#menu`). On phones only the Menu pill shows.
- Renders are the face of every project (no block massing). Each project's cover is its `cover` image (default `<slug>/render.webp`); home cards and the footer strip use it, with a slight zoom on hover. Event photos are supporting proof on project pages, labelled "On site".
- Home Selected work copies the portfolio cards on fabric.codebydennis.com (Nicholas asked for a close copy, small glitches included): `.pcards` holds one `.pcard` per project, four across on desktop split by hairlines, a snapping sideways row on narrower screens. Each card: a light pill with the project label, the client logo (white mask from the brand files; the client name in display type when there's no file), client name, title in grey, and a bottom bar "View project" with a round arrow. On hover the project's cover image fades in behind the text (darkened so the text stays readable), the card lifts 7px up and right and leaves an outline where it was, the pill text slides up and is replaced by its copy, the arrow slides out and back in, name and title scramble (`data-scramble`, characters `XYZxyzabc0$€£`, 0.6s, on enter and leave), and a dark pill follows the cursor with the project name, scrambled in (`data-cursor-text`; it sits left of the cursor on right-hand cards). The section heading scrambles in when scrolled into view (`data-scroll-scramble`). On touch screens (`hover: none`) there is no hover: each card shows its image from the start, with no lift, scramble or cursor pill (one CSS rule, plus the scramble listeners only attach on hover devices). The old flipping shelf was removed as too distracting. Their pill shows an index number (N.001); ours shows the project type instead, per the no-numbers rule.
- Brand carousel: client logo files supplied by Nicholas, in `public/assets/img/brands/<slug>.svg|png|webp` (names in that folder's README), with no boxes and generous space between logos, drifting slowly left (pure CSS, two copies for a seamless loop, paused on hover; with reduced motion a still wrapping grid). They render as masks in muted red (`--logo`) and turn white on hover. A brand without a file shows its name as a small mono placeholder. Only use logo files Nicholas provides; never draw or trace one.
- Images sit in rounded tiles (`--radius`) with a tight 8px gap.
- A small plain white dot trails the cursor with a slight delay on every page (`.cursor-dot`, faint shadow for light backgrounds). It settles just above and to the right of the pointer (+16px, -14px), never on top of it; the cursor pill sits below. Pointer devices only, no delay with reduced motion.
- Motion only answers the visitor or marks one moment: hero crossfade, menu opening, tile hover, sections fading up on scroll, and the curtain. Respect `prefers-reduced-motion` (the curtain and intro are skipped entirely).
- Curtain (after Dennis Snellenberg): first visit per browser session shows the intro: a deep red screen (`--curtain`) cycles "• Hello" through greetings, then lifts with a curved bottom edge. Internal links raise the curtain with a curved top edge and "• <page name>", then navigate; the next page opens covered and lifts. The `<head>` script sets `is-intro` / `is-entering` and `data-curtain` before paint; CSS does the lifting, `site.js` only cycles words and handles leaving (navigates when the rising curtain's animation ends). The leaving and arriving labels sit at exactly the same spot so the hand-off is invisible. Pages are prefetched on hover (speculation rules in `<head>`), and a cross-document view transition holds the frame between pages so there's no flash. Link labels come from `data-label` (project links use the client name) or the page name.

## Copy
- parahouse is premium, in a quiet-luxury way: the site never talks about money. No prices, rates, fees, discounts, credits, "cheaper", salaries or "no obligation", and no explaining why there are no prices. Commercial terms (pitch fees, the partial credit if a pitch is awarded, rates) are discussed privately after a brief. Argue value: judgement, real-dimension design, one team from pitch to build, a few projects at a time.
- No email address or phone number anywhere on the site, including error messages: every enquiry goes through the brief form.
- No decorative numbers or counts anywhere (no "(16)" beside headings, no "4+", no 001/01 indexes). Nicholas has designed for more brands than are listed, so a count undersells him.
- Written to agencies: the reader is an account director or creative lead with a pitch coming. Say "your client", "your team", "your fabricator"; never address the brand directly. Cover creative work as a whole, 2D and 3D (concept, 3D and rendering, 2D graphics, drawings and artwork), not just 3D. Be sharp about the agency's return: pitches that win, capacity without headcount, the client relationship and margin stay theirs, fewer costly surprises on site. Key promises: we work under your name, we don't contact your client unless asked, design your fabricator and printer can produce.
- Don't promise turnaround times, revision rounds or on-site work unless Nicholas gives them.
- Plain, specific, no hype words. Write in sentence case; CSS handles the uppercase for headings and labels.
- Calls to action: "Let’s talk" (footer) and "Send brief" (form). Contact person: Nicholas (not named on the site).

## Every page shares
The same `<head>` (including the inline theme script), the floating controls, the `#menu` panel and the footer (not on Home). If you change one, change all of them (`public/**/*.html`, including `404.html`).

## Adding a project
1. Copy a folder in `public/portfolio/` and rename it with a lowercase-hyphen slug.
2. Update: `<title>`, meta description, `og:` tags, `<h1>`, the four meta items (Client, Event, Type, Scope), summary, body, image paths and alt text, and pick the project's `hue` from its main colour (judge by eye from the renders; an automatic average gets fooled by carpets and studio walls).
3. Images go in their own folder, `public/assets/img/projects/<slug>/`: `cover.webp` (16:10 crop, for cards, the home hero and the Work grid), `second.webp` (footer strip) and `img-01.webp`… for the project page at the photos' original proportions (no cropping; Nicholas asked for this). Instagram collage posts are split into their panels, each kept at its own shape. On the page (`.media.mosaic`): `full` spans the row, `duo` pairs two images of the same shape, `solo` centres a single portrait. Up to 2000 px, under 400 KB. Renders first ("The render"), then photos ("The build"), or one "The event" section for photo-only projects. Every image Nicholas shares goes on the page; none are left out.
4. Add it to `PROJECTS` with the right `type` (`exhibitions` | `roadshows` | `events`) and a clear scope; the Work grid card, its filters and the home shelf come from that.
5. Optionally add it to the home showcase: one `<img>` in `[data-showcase-media]` and one `<li>` in `[data-showcase-list]`, in the same position. The link's `data-meta` fills the top-right label.
6. Fix the `.next-pill` links so every project points to the next and the last loops to the first.

## Processing a submission
New projects arrive in `submissions/<slug>/` (outside `public/`, so never published): `project.md` (filled from `_template/project.md`), `renders/`, `photos/`.
1. Read `project.md`. If "OK to show publicly" is No, stop and ask Nicholas.
2. Pick the strongest render as the cover; use every render and photo Nicholas shares on the project page, renders first. Never leave an image out, even if it looks repetitive (Nicholas asked for this); order and pairing are the place to handle repetition. Show Nicholas a contact sheet of the picks before publishing if the choice isn't obvious.
3. Resize to 2000 px on the long side (no cropping), WebP, under 400 KB, into `public/assets/img/projects/<slug>/`. Use only the images Nicholas wants shown (for ORA 5, launch day only; the pre-launch set is not used).
4. Build the project page and tile as in "Adding a project", using his wording, tightened. Add it to the home features only if he said Yes.
5. Delete the `submissions/<slug>/` folder in the same commit.
